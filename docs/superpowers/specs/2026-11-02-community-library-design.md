# 社群書房設計

## 目標

讓讀者像挑選小說一樣瀏覽並練習公開文章。文章有封面、簡介、喜歡數、練習次數與打字排行，讀者可以留言，也可以分享自己的文章。以 `community-preview.html` 的書房版面作為視覺方向。

## 瀏覽與互動

- 首頁顯示精選文章、可搜尋及排序的書架、文章封面、標題、作者、分類、喜歡數和練習次數，並提供排行與近期留言入口。沒有資料時顯示真實空狀態，不使用示意數字。
- 文章詳情顯示簡介、原文預覽、封面、留言、按讚數、練習次數和該文章的打字排行，並可開始練習。
- 訪客無須登入即可瀏覽、練習、按讚與留言。訪客可輸入顯示暱稱，未輸入時顯示「匿名讀者」。登入者使用帳號名稱；公開顯示內容不包含電子郵件。
- 建議按讚採每篇文章每個訪客或帳號一次，可取消。匿名身分以瀏覽器隨機識別，登入帳號以帳號識別；匿名識別不能保證防止重複投票，不宣稱可防刷票。
- 練習次數由完成文章練習的伺服器紀錄統計。文章排行以該文章完成練習的 WPM 排序，顯示正確率及練習者名稱；未完成的練習不列入。初版不宣稱能完全防止作弊。
- 提供輸入長度與請求頻率限制、文字安全處理，以及管理者移除違規留言與文章的方式。上線前須確認管理方式與實際部署環境。

## 上傳與封面

- 沿用現有教材匯入及公開分享流程，上傳者可選擇提供文章封面；沒有封面或封面無法顯示時使用預設封面。
- 封面以伺服器保存的圖片檔提供，限制格式與大小並驗證實際內容；不直接載入任意外部圖片網址。上傳者需有權分享文章及圖片。
- 保留現有公開教材和其下架憑證；既有教材沒有封面時使用預設封面。

## 身分與個人書架

- 訪客不必登入；支援 Google 登入後，可跨裝置查看自己的已讀文章、練習進度與成績。
- 訪客的個人練習進度仍保存在目前瀏覽器。登入後的新練習儲存到帳號；是否匯入登入前的本機資料應在介面清楚說明並由使用者選擇，避免覆寫既有紀錄。
- Google 登入需要部署時設定 OAuth 憑證、回呼網址和安全的 session；不把憑證寫入前端或版本庫。

## 實作方式的取捨

- 建議擴充現有 Python 伺服器與 SQLite 公開教材資料庫，沿用目前的前端與練習流程，新增帳號、互動、圖片與紀錄。可保留既有資料，但上線環境必須提供持久儲存與備份。
- 另一種方式是導入外部身分與資料平台，可減少自行維護帳號及儲存，但需選擇供應商、設定帳號並考慮服務費用與資料遷移。除非現有部署條件不適合，先沿用現有架構。

## 驗收

- 手機及桌機可搜尋、瀏覽、預覽與開始練習；封面缺失時顯示預設封面。
- 匿名讀者可按讚、取消及留言；登入後可跨裝置讀取個人進度和成績。重新整理後共用數字與留言仍存在。
- 每篇文章的排行與完成次數可由實際完成紀錄驗證，舊公開教材仍可瀏覽、加入及由原持有者下架。
- 涵蓋空狀態、無效封面、重複操作、資料庫重啟、翻譯與登入失敗、存取權限以及手機操作的測試。
